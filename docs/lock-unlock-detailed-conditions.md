# 从未锁定到弹窗、锁定再到解锁的详细条件

> 按当前代码（`src/BleUnlockService/Core/ProximityStateMachine.cs`）整理，已包含 2026-10-31 的改动：锁屏提示出现后，信号回到锁定阈值以上即撤回提示。
> 下文数字均为**默认值**，都可以在管理器「配置」页修改。

## 〇、默认参数

| 参数 | 默认值 | 作用 |
|---|---|---|
| 锁定阈值 | **-80 dBm** | 读数**低于**它，算「离开」证据；锁屏提示出现时，读数**高于**它，算「人回来了」 |
| 解锁阈值 | **-65 dBm** | 锁屏后，读数**高于**它才算「靠近、可以解锁」 |
| 弹窗触发个数 | **5** | 触发后再连续 5 个低于 -80，才弹出锁屏提示 |
| 锁屏确认个数 | **10** | 提示出现后再连续 10 个低于 -80，才锁屏 |
| 解锁确认个数 | **3** | 触发后再连续 3 个越过阈值：锁屏后用于解锁（阈值 -65），提示期间用于撤回提示（阈值 -80） |
| 采样间隔 | **0 毫秒** | 0 表示每条广播都计入 |
| 启动宽限 | **15 秒** | 服务启动或从睡眠恢复后，这段时间内不判定离开 |
| 解锁等待超时 | **20 秒** | 推送凭据后最多等 20 秒的登录结果 |
| 无信号判离开 | **180 秒** | 完全收不到设备这么久，就算离开（0 = 关闭这条兜底；2026-11-04 起可配置，原为固定 60 秒） |
| 点「拒绝」后暂停 | **60 秒** | 这段时间内不再提示 |
| 点「稍后」后暂停 | **5 分钟** | 同上 |

## 一、哪些读数会被计入

1. **必须是目标设备的广播。** 要么设备地址和配置里的身份地址一致，要么能用 IRK 解析出它的随机地址。
2. **信号值必须有效。** -127 及以下、+127 及以上（包括 -128）是「无法测量」的占位值，直接丢弃。
3. **采样间隔。** 采样间隔大于 0 时，两次计入的读数之间至少相隔这么久；默认 0 不限制。
4. 服务**每 1 秒**判定一次，只处理上次判定之后新到的读数。读数在内存里最多保留 120 秒。

## 二、核心规则：「批次全部达标」

所有判定都用同一套规则，不取平均值：

- **触发：** 先出现一个越过阈值的读数。这个读数只用来启动批次，**本身不计入**个数。
- **收满：** 之后再收 N 个读数，**每一个**都必须越过阈值。
- **任一不达标，整批作废：** 只要中间有一个没越过阈值，已收的全部作废，要等下一个触发才重新开始。
- **离开判定：** 读数**严格小于** -80（等于 -80 不算）。
- **靠近判定：** 读数**严格大于**阈值。用哪个阈值、是否限制读数间隔，看场景：
  - 撤回锁屏提示：**-80**（锁定阈值），**读数间隔不限**（2026-11-04 起：手表可能隔十几秒才广播一次，原来的 3 秒限制会让提示永远撤不回来；撤回提示只会推迟锁屏，放宽没有风险）；
  - 锁屏后自动解锁：**-65**（解锁阈值），相邻两个读数的间隔**不能超过 3 秒**，超过就整批作废、重新数。
- **每次状态切换，进行中的批次都清零**，不会带到下一个状态。

### 「静默」怎么算（只用于离开判定）

- 停播 **3 秒以内**不算任何证据，当作偶发丢包。
- 超过 3 秒后，只有在下面**两种情况之一**时，才会**每秒补记一个 -127 的「静默值」**，计入离开批次（静默本身也可以作为触发）：
  - 停播前**已经连续 2 个读数低于 -80**：信号先变弱、再消失，这是人真正走远的样子。只有一个偶发的低读数不算（2026-11-04 起）；
  - **连续 180 秒完全没有读数**（「无信号判离开」，可配置，0 = 关闭）：设备关机、被带走或超出范围的兜底情况。手表放着不动会停止广播一两分钟，所以默认值比原来的 60 秒长。
- 停播前信号还强的话，停播**不算离开**。手机、手表会为了省电间歇停播。
- **电脑的蓝牙接收卡死时，静默也不算离开**（见第七节「蓝牙接收卡死」）。

## 三、已解锁 → 弹出锁屏提示（进入「待锁定」）

要**全部**满足：

1. 服务启动或睡眠恢复后已经超过 **15 秒**；
2. 自服务启动以来**至少见过一次**目标设备；
3. 出现一个低于 -80 的触发读数（或者静默触发）；
4. 之后再连续 **5 个**低于 -80（静默值也算）。

## 四、待锁定（提示显示中）→ 解除提示，或锁屏

提示**不会自动超时**。按判定的先后顺序，下面任一情况都会结束它：

| # | 条件 | 结果 |
|---|---|---|
| 1 | **人回来了：** 一个**高于 -80** 的触发读数，之后再连续 **3 个高于 -80**，读数间隔不限。读数正好等于 -80 不算 | 撤回提示 → **已解锁** |
| 2 | **确认离开：** 提示出现**之后**新收的读数里，连续 **10 个低于 -80**（静默值也算）。这里不需要触发读数，提示一出现就开始计数；中间只要有一个不低于 -80，这批作废，要等下一个低于 -80 的读数再重新开始 | 撤回提示并锁屏 → **已锁定·等待离开** |
| 3 | **用户点「拒绝」**（对话框模式下点「是」） | **暂缓** 60 秒 |
|   | **用户点「N 分钟内不锁定」**（对话框模式下点「否」） | **暂缓** 5 分钟 |
|   | **用户点 × 关闭通知** | 立即锁屏 → **已锁定·等待离开** |
|   | **通知被 Windows 隐藏**（勿扰、专注模式、全屏程序：系统报告「超时」，或弹出后 1 秒内就被关掉）——这不是用户操作 | 不锁屏；改用不受勿扰影响的系统对话框再提示一次，状态仍是**待锁定** |
| 4 | **手动锁屏**（Win+L 等） | 撤回提示 → **已锁定·等待离开** |
| 5 | **电脑从睡眠中恢复**（用户没看到这条提示） | 撤回提示 → **已解锁**，从头判定 |
| 6 | **提示期间凭据预验证失败**（配置里的用户名或密码被改错，服务重新加载后预验证没通过） | 撤回提示，并通知「自动解锁已暂停」 → **已挂起** |
| 7 | **提示期间收到「会话已解锁」事件**（极少见：只有先发生了一次服务没收到的锁屏才会出现） | 撤回提示 → **已解锁** |

**不会**结束提示的情况：

- 对话框到了自身的显示期限：对话框会消失，但状态仍是「待锁定」，后台继续计数；
- 在配置里换了目标设备：读数历史被清空，提示不撤回，状态不变。

**提示期间 -80 ~ -65 之间的读数：** 以前不算任何证据，现在会算作「人回来了」的证据，同时也会打断锁屏确认的计数。

**暂缓：** 这段时间不看任何读数，时间到了回到**已解锁**，从第三节开始重新判定。暂缓期间如果锁屏，进入**已锁定·等待离开**。

**锁屏怎么执行：** 先撤回提示，再请提示助手锁屏；助手没有及时确认的话，改用系统命令锁屏。

**提示怎么弹出：** 默认由提示助手弹出系统通知。配置成「对话框」模式，或者助手不可用时，改用系统对话框。正在提示时助手断开的话，会立即改用对话框重新提示一次。

## 五、已锁定·等待离开 → 已锁定·监控中

用户坐在电脑前按 Win+L 之后，**必须真的离开一次**，之后才可能自动解锁：

- 这个状态下**无论信号多强，都不会推送凭据**；
- 条件和第三节一样：启动或恢复后超过 15 秒，出现一个低于 -80 的触发读数，之后再连续 **5 个**低于 -80（静默值也算）。

服务启动时屏幕已经是锁定的，也是从这个状态开始。

## 六、已锁定·监控中 → 自动解锁

1. **判定靠近：** 一个**高于 -65** 的触发读数，之后再连续 **3 个高于 -65**，相邻间隔不超过 3 秒。
   → 进入**解锁确认中**，推送凭据。
   注意：这里仍然是 -65，-80 ~ -65 之间的信号**不会**解锁。
2. **推送凭据的前提**（不满足就跳过这一次）：
   - 锁屏界面上的凭据提供程序**已经连上服务**。它只在锁屏界面出现时才会连接；
   - **没有连续推送 3 次都没收到登录结果**。连续 3 次没回音就暂停推送，避免账户被锁定。手动解锁或修改凭据后，这个计数清零。
3. **等待登录结果**，最多 **20 秒**：
   - **成功：** 回到**已解锁**；
   - **失败，且原因是**「用户名或密码错误」「密码已过期」「必须先修改密码」「账户已被锁定」之一：进入**已挂起**，并通知用户；
   - **其他原因失败：** 回到**已锁定·监控中**，等下一次靠近再试；
   - **20 秒内没有结果：** 回到**已锁定·监控中**，之后重试。

## 七、任何时候都适用的情况

- **手动解锁：** 除了**已挂起**以外，都会回到**已解锁**，同时清零第六节那个「连续 3 次」的计数。
- **手动锁屏：** 除了**已挂起**以外，都会进入**已锁定·等待离开**；如果当时正在提示，先撤回提示。
- **从睡眠中恢复：** 清空读数历史，重新给 15 秒宽限，「最后一条读数」也清空（睡眠的时间不算静默）；正在进行的批次全部作废。
- **凭据预验证失败**（服务启动时，或者修改了用户名、密码时）：进入**已挂起**并通知用户；如果当时正在提示，先撤回提示（见第四节第 6 条）。
- **已挂起：** 不看读数，也不响应锁屏和解锁事件。改成正确的凭据并通过预验证后才恢复：屏幕锁着就回到**已锁定·等待离开**，没锁就回到**已解锁**。
- **蓝牙接收卡死：** 扫描显示在运行，但连续 **30 秒**收不到周围**任何设备**的广播（不只是手表），就判定为电脑的蓝牙接收卡死了（例如蓝牙驱动超时）。卡死期间：
  - 静默**不再补记**，所以不会因为「没信号」而弹出提示或锁屏，也不会因此进入**已锁定·监控中**；真实读数照常计算；
  - 如果当时正在提示，撤回提示 → **已解锁**；如果已经在**已锁定·监控中**，退回**已锁定·等待离开**，恢复后要重新确认离开才会自动解锁；
  - 自动恢复：先重启扫描；30 秒后还收不到，就重启蓝牙适配器（蓝牙耳机、鼠标会断开几秒再自动重连）；再过 60 秒还不行，就通知你手动关闭再打开蓝牙或重启电脑，之后每 5 分钟再自动试一次；
  - 检测到卡死和恢复失败时各弹一次托盘通知，管理器概览页的「BLE 扫描」也会显示这个状态；恢复成功只记日志；
  - 重新收到任何广播即算恢复：静默从恢复那一刻重新计时，卡死前的最后一条读数也作废（和睡眠恢复一样）。
- **还没设置完成**（新装的电脑，2026-11-02 起服务照常启动，不再因为缺配置而拒绝启动）：
  - **没有选择设备**（设备为空，或解除配对后写入的全零占位）：不监测任何设备，既不弹提示、不锁屏，也不解锁。服务照常提供已配对设备列表，管理器打开时自动进入设置向导；
  - **选了设备，但没有 Windows 用户名或密码**：离开照常提示、锁屏；但**已锁定·等待离开**不会再进入**已锁定·监控中**，所以回来不会自动解锁。这不是**已挂起**（那是密码填错的情况）；如果当时已经在**已锁定·监控中**或正在发送凭据，退回**已锁定·等待离开**；
  - 每次登录时托盘通知一次缺什么；管理器概览页和托盘图标也会显示；
  - 在管理器里补全设备或密码后立即生效，不用重启服务；
  - 配置文件里原本有设备或凭据、重新加载时却变成空值（多半是文件还没写完或已损坏），服务拒绝这次加载并保留原配置。要移除设备，请在管理器里「解除配对」。

## 八、按默认值走一遍

**离开、锁屏、回来解锁**

1. 人起身离开，读数降到 -82，这是**触发**，不计入。
2. 接下来 5 个读数都低于 -80 → **弹出提示**。
3. 提示出现后再收 10 个低于 -80 的读数（走远后收不到信号，每秒补记一个静默值也算）→ **锁屏**。
4. 继续收不到信号，再补记 5 个静默值 → 进入**可解锁**状态。
5. 人回来，读数升到 -60，这是**触发**；之后 3 个都高于 -65 → **推送凭据**。
6. 收到登录成功 → **已解锁**。

**提示弹出后，人又走回来**

1. 提示已经弹出，人走回来一些，读数回到 -76，这是**触发**。
2. 之后 3 个读数都高于 -80（比如 -77、-75、-74）→ **撤回提示**，回到**已解锁**，不锁屏。
