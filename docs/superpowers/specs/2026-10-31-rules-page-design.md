# 管理器「判定条件」页设计

> 状态：已获用户确认（2026-10-31）。UI 设计稿见设计画布「判定条件」一排（Rules / RulesEnDark / RulesEs / RulesFull）。

## 目的

把「从未锁定、弹窗（含撤回）、锁定到解锁」的完整判定条件放进管理器，给不看代码、不读文档的同事查看；文中数值随服务当前生效的配置变化，三种语言。

## 用户确认的决定

| 项 | 决定 |
|---|---|
| 入口 | 侧栏主导航，「日志」下方；名称：判定条件 / Rules / Reglas |
| 数值来源 | 服务当前生效的配置（磁盘上的 `appsettings.json`）；配置保存并被服务重载后自动更新 |
| 详细程度 | 与 `docs/lock-unlock-detailed-conditions.md` 一样完整，共 0–8 节 |
| 形式 | 顶部状态流程图 + 分节文字 |
| 流程图 | 实时高亮服务当前状态，方块内显示批次进度；点击方块滚动到对应小节 |
| 第 8 节例子 | 读数按当前设置推算 |
| 读不到配置 | 用默认值，并在顶部提示 |
| 文档 | 保留 `docs/lock-unlock-detailed-conditions.md`，删除 `docs/lock-unlock-conditions.md`，链接改指向保留的那份 |

## 做法

- **内容生成（Manager.Core，可单元测试）：**
  - `RuleValues`：从 `BleUnlockConfig` 取 10 个数值，并提供默认值；
  - `RuleExamples`：按阈值推算例子读数；
  - `RulesContent`：用 `UiStrings` 中带命名占位符（`{lock}`、`{prompt}` 等）的模板生成各节文字。
- **页面（WPF）：** `RulesPage` + `RulesViewModel`。
  - 流程图：固定 960×360 画布，箭头用 Path，状态方块是按钮；
  - 分节：ItemsControl + 数据模板；
  - 实时状态和批次进度来自 `TelemetryStore`（`StateName`、`Batch`）。
- **刷新时机：**
  - 页面显示时读取配置；
  - 页面可见期间，每 2 秒检查一次 `reload-status.json`，出现新的 Id 就重新读取；
  - 语言切换后重建全部文字。
- **固定值：** 3 秒静默宽限、60 秒兜底、-127 静默值、连续 3 次推送暂停、每秒判定一次、读数保留 120 秒，这些在代码里写死，页面上照常写出来。

## 验收

1. 侧栏出现新项，点击打开页面，三种语言下名称和全部文字正确切换。
2. 修改配置（例如锁定阈值 -75）并保存后，页面数值、参数表的「默认值」标注、第 8 节例子都随之变化。
3. 流程图高亮服务当前状态，进行中的批次显示进度；点击方块滚动到对应小节。
4. 服务未安装或读不到配置时，显示默认值，并在顶部提示。
5. 全部测试通过，其中资源一致性检查和「无写死中文」检查也要通过。
