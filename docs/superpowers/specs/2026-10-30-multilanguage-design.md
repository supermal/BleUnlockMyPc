# AutoUnlock 多语言（中文 / English / Español）设计

> 状态：已获用户确认（2026-10-30）。

## 1. 目的与背景

AutoUnlock 要拿到其他电脑上，给不一定懂中文的同事使用。目前所有用户可见的文字都是写死的中文。本设计让用户在设置中选择语言，并让**所有用户可见的文字**都跟随这个选择。

## 2. 目标

1. 管理器「设置」页新增「语言」选项：**跟随系统（默认）/ 中文 / English / Español**。
2. 跟随系统：系统显示语言是中文、英文或西班牙语时用对应语言，其他语言一律用**英语**。
3. 范围是**全部用户可见文字**（用户原话：「要完全」「全部」）：
   - 管理器：所有页面、对话框、配对流程、托盘图标的提示文字与右键菜单、托盘速览、校验与错误提示、横幅、导出提示等。
   - 提示助手：离开时的「是否锁屏」通知及其按钮，以及助手显示的其他通知。
   - 服务：发给用户的通知文字（经助手 toast，或降级的对话框模式），以及**写入文件的运行日志**。
   - 安装 / 卸载脚本运行时的输出与交互提示；测试包中的安装说明。
4. 在设置中切换后**立即生效**：管理器界面无需重启即刻切换；服务与助手无需重启，**之后**产生的通知与日志使用新语言。
5. 设置**整台电脑一份**（同事电脑一般一人专用）。

## 3. 非目标

- 已写入的日志不回译；切换后同一日志文件中前后两种语言并存（用户已接受）。
- 不支持三种以外的语言，也不做按用户区分的语言设置。
- 仓库开发文档（README、docs/ 下的设计与计划）保持中文，不在范围内（我的决定，见 §9）。
- 锁屏界面的凭据提供程序（C++）没有用户可见文字，不改。

## 4. 反目标（技术上能用也算失败的情况）

- 任何界面出现语言混杂。例如英文界面中残留中文的按钮、提示、托盘菜单，或者弹出中文的锁屏提示。
- 切换语言后，某些功能因为依赖中文原文而失效。目前已知有两处，见 §6。
- 英文 / 西班牙语文字较长，导致按钮、导航、托盘速览中的文字被截断或重叠，看不懂。
- 切换语言要求重启管理器或服务。

## 5. 约束

- 现有技术栈：.NET 10，WPF 管理器（WPF-UI、CommunityToolkit.Mvvm），Windows 服务，提示助手（toast），PowerShell 5.1 脚本。
- **代码内部一律用英语**：服务与管理器、服务与助手之间传递的状态码和标记，凡不显示给用户的，都用英文且与语言无关（用户原话）。
- 代码注释用西班牙语，标识符用英语（全局约定）。
- 服务以 SYSTEM 身份运行。配置目录 `C:\ProgramData\AutoUnlock` 只允许 SYSTEM 与 Administrators 访问；助手以登录用户身份运行，**读不到**该配置。
- 管理器写配置后，服务会自动热重载（已有机制）。
- 现有测试有断言中文文字的，改造后测试必须固定语言或改为断言与语言无关的结果，不能因运行环境的语言而时过时不过。

## 6. 已定的做法

### 6.1 设置存放

- 语言是**整机一份**，存在服务配置 `appsettings.json` 中（例如 `AutoUnlock:Ui:Language`），取值 `system | zh | en | es`，缺省为 `system`。
- 管理器的「设置」页读写这个值，保存后由服务热重载。
- 主题仍保留在当前的用户本地设置中，不变。

### 6.2 「跟随系统」如何判定

- 判定规则：UI 语言是 `zh` 系（含 zh-CN / zh-TW / zh-HK / zh-Hans / zh-Hant 等）→ 中文；`en` 系 → 英文；`es` 系 → 西班牙语；其他 → 英文。
  - 繁体也归为中文，界面显示简体（我的决定）。
- **管理器**：用当前用户的 Windows 显示语言判定。
- **服务**：以 SYSTEM 运行，自身的 UI 语言是整机默认语言，不一定等于用户的显示语言。做法如下（我的决定）：
  - 助手连上服务时，上报登录用户的 UI 语言；
  - 服务在 `system` 模式下以助手上报的为准；
  - 助手连上之前（例如开机初期），先用整机默认 UI 语言。

### 6.3 服务 → 助手

- 助手看不到配置，由服务通过现有的助手管道告知生效语言（新增与语言无关的英文命令或字段）。语言变化时要立即告知已连接的助手。
- 助手自己的提示文字（锁屏提示标题、正文、按钮）按服务告知的语言显示。
- 服务发来的通知正文由服务按当前语言生成。

### 6.4 去掉「依赖中文原文」的两处判断（必须）

1. **BLE 扫描状态**：概览页「BLE 扫描是否正常」，现在靠比对服务遥测中的中文状态文字（`TelemetryFormat.ClassifyScan`）。
   - 改为：服务在遥测快照中提供英文状态码，管理器按状态码判断。
   - 显示给用户的说明文字按语言生成。
2. **配置是否被服务接受**：配置页现在靠在服务日志中搜中文关键词「配置已重载」「配置校验失败，已保留原配置」（`ConfigReloadWatcher`）。
   - 改为：不再依赖日志文字。具体用什么与语言无关的通道（例如遥测快照中的重载结果、结构化日志属性等）由施工者决定。
   - 被拒绝时显示给用户的原因要按语言显示。

施工时还要全面排查是否有其他「靠文字判断状态」的地方，一并改掉。

### 6.5 管理器即时切换

- 切换后，XAML 中的文字和代码生成的文字（视图模型、托盘提示与菜单、格式化文字、校验提示、对话框）都要立即刷新，无需重启。
- 已显示的横幅、对话框可以保持原文，直到下一次刷新（我的决定）。
- 日期、时间、数字格式：日志文件时间戳格式不变；界面上的相对时间（例如「3 分钟前」）、时长等按语言翻译；dBm 数值保持现有格式。

### 6.6 运行日志

- 服务写入的日志消息按当前生效语言输出，切换后新写的日志即为新语言。
- 管理器「日志」页按级别过滤、计数的功能不能依赖消息文字（目前按级别字段解析，应保持如此）。

### 6.7 脚本与安装说明

- `install.ps1`、`uninstall.ps1` 运行时按系统 UI 语言（`Get-UICulture`）选择中 / 英 / 西输出，规则同 §6.2。
  - 卸载时的确认输入（目前要求输入 `yes`）在三种语言下都要能用。
- 脚本需能在 PowerShell 5.1 下正确显示三种语言，注意文件编码（含 BOM）。
- 安装说明提供三份：中文（现有）、英文、西班牙语；测试包中三份都要放。

### 6.8 翻译

- 英文和西班牙语由施工者翻译，用词统一（建一份术语表：服务 / 助手 / 管理器、锁屏 / 解锁、阈值、配对、IRK 等）。
- 西班牙语由用户审阅（用户能读西班牙语）。

## 7. 验收标准

1. 设置中选择 English / Español / 中文后，管理器所有页面、对话框、配对流程、托盘提示、右键菜单、速览**立即**切换，无任何残留其他语言的用户可见文字。
2. 选「跟随系统」时，在中 / 英 / 西系统显示语言下分别显示对应语言；在其他语言（例如法语）下显示英语。
3. 切换后（不重启服务），下一次锁屏提示、服务通知、新写的日志都是新语言。
4. 在英文、西班牙语下：概览页 BLE 扫描状态判断正确；配置页保存后能正确显示「已应用」或「被拒绝及原因」。
5. 英文、西班牙语下，按最小窗口尺寸（800×500）和托盘速览宽度检查，没有关键文字被截断到看不懂。
6. 安装 / 卸载脚本在三种系统语言下输出对应语言；卸载确认在三种语言下都能用。
7. 所有现有测试与新增测试在任意系统语言下都能通过。

## 8. 留给施工者决定的

- 资源格式与组织方式（例如 .resx 卫星资源、XAML 资源字典或其他），以及 XAML 即时刷新的实现方式。
- 语言值在配置中的具体键名，管道协议中新增命令或字段的具体形式。
- §6.4 第 2 点改用的具体通道。
- 服务端日志本地化的具体实现，例如消息模板如何按语言选择。

## 9. 我做的决定（请审阅）

- 繁体中文系统归到中文，界面显示简体。
- 服务在「跟随系统」时，以助手上报的登录用户语言为准；助手连上之前用整机默认语言。
- 已显示的横幅、对话框在切换语言时可以保持原文，下次刷新再更新。
- 仓库开发文档（README、docs/）保持中文，不翻译。
- 语言设置存在服务配置里，主题仍存在用户本地设置里。
- 服务未安装、配置文件不存在时：管理器按「跟随系统」显示；语言选项禁用，并提示需先安装服务。
- 写入 Windows 事件查看器的服务事件，与运行日志同源，同样跟随语言。
- 无障碍名称（屏幕阅读器读出的 AutomationProperties.Name）也属于用户可见文字，一并翻译。
- **服务显示名与描述固定用英文**（用户决定），不随语言变化。
- 其他安装时写入系统的名称（开始菜单快捷方式名、计划任务描述）按**安装时**的系统语言确定，之后在设置里切换语言不会改它们。
- 切换语言时，正在显示的锁屏提示保持原文，下一次提示才用新语言。
- 品牌名「AutoUnlock」在三种语言中都不翻译。
