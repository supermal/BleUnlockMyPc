# BleUnlock

基于蓝牙低功耗（BLE）信号强度的 Windows 11 近距离自动锁屏与自动解锁。

带着手表或手机离开电脑，信号变弱，BleUnlock 先弹出提示，确认你真的走远后锁屏；回到电脑前，信号变强，锁屏界面自动登录。整个过程不需要在手机或手表上安装任何 App。

## 一、工作原理

### 1. 怎么认出你的设备

iPhone、Apple Watch 和大多数现代手机、手表为了防跟踪，会使用**可解析私有地址（RPA）**：广播地址每隔十几分钟就换一次，光看地址认不出是谁。

设备与电脑完成**配对**时，会把一个 16 字节的**身份解析密钥（IRK）**交给 Windows。拿着 IRK 就能验证某个随机地址是否属于这台设备。BleUnlock 的服务以 SYSTEM 权限从 Windows 蓝牙配对库读取这个 IRK，用它在周围所有广播中挑出你的设备。

- 有些设备会直接用固定的**身份地址**广播，这时按地址匹配，不需要 IRK。
- 配对时不提供 IRK 的设备（例如只能和自家 App 配对的手环）无法使用，管理器里会标记为「不支持」。

### 2. 怎么判断你走远了还是回来了

服务持续接收目标设备的广播，读取每条广播的信号强度（RSSI，单位 dBm，数值越接近 0 越强）：

- 读数持续**低于锁定阈值**（默认 -80 dBm）：判定为离开 → 先弹提示，再锁屏；
- 锁屏后读数持续**高于解锁阈值**（默认 -65 dBm）：判定为靠近 → 推送凭据，自动登录。

判定不取平均值，而是要求**连续一批读数全部达标**，任何一条不达标整批作废、重新计数。这样偶发的一两个低读数不会造成误锁，代价是信号在阈值附近抖动时判定会慢一些——宁可慢，不误判。详见[第九节](#九判定规则概要)。

### 3. 怎么完成自动登录

锁屏界面上有一个 BleUnlock **凭据提供程序**。判定为靠近时，服务把加密保存的 Windows 用户名和密码推送给它，由它交给 Windows 完成登录，相当于替你输入了密码。

> 必须是**密码**，不能是 PIN。

### 4. 支持的账户类型

| 账户 | 用户名怎么填 | 解锁时怎么提交 |
|---|---|---|
| 本地账户 | `Admin`、`.\Admin` 或 `电脑名\Admin` | MSV1_0（本机认证包） |
| 域账户 | `域\用户名`（如 `TELEAPOSTUAK\hq.qiu`）或 UPN（如 `hq.qiu@kirol.es`） | Negotiate（Kerberos，必要时 NTLM 或缓存凭据） |
| 微软（Outlook）账户 | 邮箱（如 `name@outlook.com`）或 `MicrosoftAccount\邮箱` | Negotiate |

- 设置向导会**自动填好当前登录的账户**：域账户带上域名，微软账户填成 `MicrosoftAccount\邮箱`，一般不用改。
- 服务会把填写的名字解析成 Windows 认可的规范形式（例如 `hq.qiu@kirol.es` → `KIROL\hq.qiu`，只填 `hq.qiu` 也能在域里找到），再交给凭据提供程序；解析不了（如暂时连不上域控制器）就按原样使用。
- 密码在提交前用 `CredProtect` 保护，与 Windows 自带的密码登录方式一致。
- 域账户：电脑暂时连不上域控制器时，服务不会因为「无法预验证」而暂停自动解锁，以锁屏时 Windows 的实际登录结果为准（离线时 Windows 会用缓存凭据）。
- Microsoft Entra ID（工作或学校账户，`AzureAD\…`）尚未验证。

## 二、主要功能

- **离开自动锁屏**：先弹出可取消的提示（「拒绝」「N 分钟内不锁定」），确认离开后再锁屏。
- **靠近自动解锁**：锁屏后回到电脑前，自动登录。
- **防误解锁**：坐在电脑前按 Win+L 后，必须真的离开一次再回来才会自动解锁。
- **新电脑开箱即用**：服务不再因为缺配置而拒绝启动；管理器自动打开 3 步**设置向导**（选设备 → 填账户 → 保存）。
- **在管理器里直接配对**：支持「手机 / 手表」（电脑广播，由设备发起连接）和「耳机 / 鼠标 / 键盘」（电脑扫描并发起配对）两种方式，配对确认与 PIN 在窗口内完成。
- **只锁不解模式**：选了设备但不填密码时，只自动锁屏，不自动解锁。
- **实时概览**：信号曲线（靠近区 / 保持区 / 离开区）、锁定周期与批次进度（如「离开确认 3/5」）、服务健康状态。
- **判定条件页**：用当前配置的实际数值解释每一条锁屏 / 解锁规则。
- **蓝牙卡死自愈**：检测到电脑蓝牙接收卡死时不会误锁屏，并自动重启扫描或蓝牙适配器。
- **配置热重载**：大部分配置保存后立即生效，不用重启服务。
- **敏感信息加密**：IRK 和密码用 Windows DPAPI 加密保存。
- **三种语言**：中文 / English / Español，覆盖管理器、提示、通知、日志和安装程序。
- **单文件安装包**：一个 exe 包含所有组件和运行库，目标电脑无需预装 .NET。

## 三、组件与架构

| 组件 | 文件 | 运行身份 | 职责 |
|---|---|---|---|
| 服务 | `BleUnlockService.exe` | Windows 服务（LocalSystem），服务名 `BleUnlockService`，显示名「BleUnlock Proximity Unlock」 | BLE 扫描、设备匹配、状态机判定、锁屏决策、推送凭据、读取配对库、向管理器提供遥测 |
| 提示助手 | `BleUnlockHelper.exe` | 在用户的交互会话中运行（由服务拉起） | 弹出锁屏提示（Toast 通知或对话框）、执行锁屏（`LockWorkStation`）、把用户的选择和执行结果回传服务 |
| 凭据提供程序 | `BleUnlockCredentialProvider.dll`（安装后为 `BleUnlockCP.dll`） | 由 Windows 登录界面（LogonUI）加载 | 锁屏界面出现时连上服务，接收凭据并提交给 Windows 登录 |
| 管理器 | `BleUnlockManager.exe`（WPF + WPF-UI） | 当前用户，以最高权限运行；托盘常驻 | 概览、配置、配对、日志、判定条件、设置向导、语言与主题 |

组件之间都用**本地命名管道**通信，不开任何网络端口：

| 管道 | 连接方向 | 用途 |
|---|---|---|
| `BleUnlockHelper` | 助手 → 服务 | 锁屏提示、用户选择、锁屏执行结果 |
| `BleUnlock` | 凭据提供程序 → 服务 | 推送凭据、回传登录结果 |
| `BleUnlockManagement` | 管理器 → 服务 | 每 250 ms 一帧的遥测快照（状态、读数、批次进度、设置是否完成等） |
| `BleUnlockBleBonds` | 管理器 → 服务 | 读取 Windows 已配对 BLE 设备列表（含 IRK，仅限 SYSTEM / 管理员） |

```
         ┌────────────── 用户会话 ───────────────┐
         │  BleUnlock 管理器        提示助手        │
         │   (托盘/窗口)          (Toast/对话框)    │
         └──────┬───────────────────────┬──────────┘
   遥测/配对列表 │                       │ 提示/锁屏
         ┌──────▼───────────────────────▼──────────┐
 BLE 广播 →           BleUnlockService             │
         │   扫描 → 匹配(IRK) → 判定 → 锁屏/解锁    │
         └─────────────────────┬────────────────────┘
                     推送凭据    │
         ┌─────────────────────▼────────────────────┐
         │   锁屏界面：BleUnlock 凭据提供程序 → 登录  │
         └───────────────────────────────────────────┘
```

## 四、系统要求

- Windows 11 x64（安装包最低要求 Windows 10 1809，但只在 Windows 11 上验证过）
- 支持 BLE 的蓝牙适配器（大多数笔记本内置的都可以）
- 一台会在配对时提供 IRK 的设备：Apple Watch、iPhone、多数安卓手机和手表
- 本地账户、域账户或微软（Outlook）账户的 **Windows 密码**（不是 PIN），见[支持的账户类型](#4-支持的账户类型)
- 安装需要管理员权限

使用单文件安装包时，**.NET 运行时和 Visual C++ 运行库都已包含在内**，无需单独安装。

## 五、安装（推荐：单文件安装包）

1. 双击 `BleUnlock-Setup-<版本>.exe`，按提示安装。安装程序语言自动跟随 Windows 显示语言（中 / 英 / 西）。
2. 安装程序会依次：
   - 安装 Visual C++ 运行库（已装过同版本或更新版本则跳过）；
   - 安装服务、提示助手、凭据提供程序和管理器到 `C:\Program Files\BleUnlock`；
   - 启动服务和管理器。
3. **不需要重启**。锁屏界面每次锁屏都会重新启动并加载凭据提供程序，装完后下一次锁屏就能自动解锁。升级时旧的凭据提供程序如果正被占用，安装脚本会把它改名让开，新版本同样在下一次锁屏生效。
4. 管理器发现还没选择设备，会自动打开设置向导，见[第六节](#六首次设置)。

**升级**：直接运行新版本的安装包，覆盖安装即可，原有配置保留。旧版（AutoUnlock 时期）的安装会被识别为升级并自动清理。

**卸载**：在「设置 → 应用 → 已安装的应用」里卸载 BleUnlock。卸载时会询问是否同时删除配置和日志（默认「否」，保留以便以后重装）。不需要重启。

**安装日志**：安装失败时，详细信息记录在 `C:\ProgramData\BleUnlock\setup.log`。

## 六、首次设置

### 设置向导（3 步）

新电脑第一次打开管理器时自动出现；之后可以在「概览」页的黄色提示条上点「运行设置向导」再次打开。向导可以随时跳过。

1. **选择解锁设备**
   - 列表里是已与这台电脑配对的蓝牙设备。显示「不支持」的设备没有 IRK，不能选。
   - 还没配对：点「配对新设备…」在管理器里配对，或点「打开 Windows 蓝牙设置」用系统方式配对，配好后点「刷新」。
   - 点「不知道怎么配对？」可以看到不同设备的配对方法（见下表）。
2. **填写 Windows 账户**
   - 用户名已自动填好当前登录的账户（域账户带域名，微软账户为 `MicrosoftAccount\邮箱`），一般不用改。
   - 密码是 Windows 登录密码，不是 PIN。
   - 也可以点「暂不填写」：这样只自动锁屏，回来不会自动解锁。
3. **保存**：立即生效，不用重启服务。服务如果没在运行，向导会自动启动它。

### 各类设备怎么配对

| 设备 | 方法 |
|---|---|
| **Apple Watch** | 点「配对新设备…」→ 选「手机 / 手表」→ 开始广播；然后在手表上打开「设置 › 蓝牙」，在「健康设备」里点这台电脑。 |
| **iPhone** | 系统蓝牙设置里看不到电脑。点「配对新设备…」开始广播后，用 nRF Connect 等蓝牙工具 App 连接这台电脑并确认配对。 |
| **安卓手机** | 点「打开 Windows 蓝牙设置」→ 添加设备 → 蓝牙，同时在手机上打开蓝牙设置页并保持可被发现。配对后如果显示「不支持」，改用「配对新设备…」的广播方式，用 nRF Connect 连接。 |
| **手环和其他手表** | 先让它进入配对模式，点「配对新设备…」→ 选「耳机 / 鼠标 / 键盘」扫描并配对。很多手环只能和自家 App 配对，这类设备无法使用。 |

### 没有完成设置时会怎样

| 情况 | 行为 | 托盘与概览 |
|---|---|---|
| 没有选择设备 | 服务照常运行，但不监测任何设备：不弹提示、不锁屏、不解锁 | 托盘显示「需要设置」（黄色 ▲），概览页显示提示条 |
| 选了设备，没填用户名或密码 | 离开照常提示并锁屏；回来**不会**自动解锁 | 同上；正在离开时优先显示「离开确认中」 |

每次登录 Windows 时，托盘会通知一次缺少什么。补全后立即生效。

## 七、日常使用

### 离开时

1. 信号连续变弱 → 弹出锁屏提示（默认是 Windows 通知）。
2. 提示上可以选择：
   - **拒绝**：60 秒内不再提示；
   - **N 分钟内不锁定**：默认 5 分钟内不再提示；
   - **关闭通知（×）**：立即锁屏。
   - 通知被 Windows 隐藏（开着勿扰、专注模式或全屏程序）不算你点了 ×：不会锁屏，改用系统对话框再提示一次。
3. 不做任何操作，信号继续变弱 → 自动锁屏。
4. 提示期间如果你走回来了（信号回到锁定阈值以上），提示会自动撤回，不锁屏。

### 回来时

1. 锁屏后服务先确认你真的离开了（信号继续低于锁定阈值一段时间）。
2. 你回到电脑前，信号连续高于解锁阈值 → 自动登录。
3. 锁屏界面要处于显示状态：屏幕关闭或停留在锁屏插图（尚未出现登录框）时，凭据提供程序还没连上服务。按任意键或动一下鼠标即可。

### 手动锁屏（Win+L）

你坐在电脑前按 Win+L，信号很强，但 BleUnlock **不会**马上替你解锁：必须先离开一次（信号变弱），再回来才会自动解锁。这是为了防止「刚锁就开」。

### 安全保护

- 连续 3 次推送凭据都没收到登录结果，暂停推送，避免账户被锁定。手动解锁或修改凭据后恢复。
- 登录失败的原因是「用户名或密码错误」「密码已过期」「必须修改密码」「账户已锁定」之一时，进入**已挂起**状态并通知你，直到在管理器里改成正确的凭据。

## 八、BleUnlock 管理器

从开始菜单「BleUnlock 管理器」打开，或在托盘双击图标。由计划任务 `BleUnlockManager` 随登录以最高权限自动启动（不弹 UAC）；手动双击 exe 会弹 UAC，属正常现象。关闭主窗口只是隐藏到托盘。

### 页面

- **概览**
  - 实时 dBm 与 5 分钟信号曲线，按阈值分为靠近区、保持区、离开区；5 秒 / 10 秒均值；
  - 锁定周期：已解锁 → 待锁定 → 已锁定·等待离开 → 已锁定·监控中 → 解锁确认中，当前步骤高亮，并显示批次进度（如「离开确认 3/5」「锁屏确认 7/10」「解锁确认 1/3」）。进度区域的高度固定，进度出现或消失时页面不会跳动；
  - 服务与健康：服务状态、BLE 扫描状态（含蓝牙卡死）、提示助手和凭据提供程序是否连上；启动 / 停止 / 重启服务；
  - 目标设备：名称、地址；
  - 未完成设置时的提示条和「运行设置向导」按钮；
  - 导出样本 CSV。
- **配置**
  - 设备、凭据、判定、通知四组卡片表单；输入即校验，原子保存，底部有「未保存的更改」栏；保存后确认服务已热重载；
  - 解锁设备从「已配对 BLE 设备」下拉框中选择，IRK 自动读取，不在界面上显示；
  - 「配对新设备…」「解除配对」；
  - 已保存的密码不回显、不可查看，只有新输入时才显示「小眼睛」。
- **日志**
  - 服务日志实时跟随：停在底部时自动滚动，向上翻看时保持位置并提示「回到最新」；
  - 按级别筛选（带计数）、关键字过滤、警告 / 错误整行高亮、导出、打开日志目录；
  - 侧栏「日志」旁显示**未读**的错误 / 警告数：有未读错误时显示红色的错误数，只有警告时显示黄色的警告数，悬停可看两者各多少；打开「日志」页即清零。「已读到哪里」按日志时间记录并保存，重启管理器、日志换天都不会重新计数。
- **判定条件**：用当前配置的数值逐条解释从弹窗、锁屏到解锁的规则，随配置变化自动更新。内容与 [`docs/lock-unlock-detailed-conditions.md`](docs/lock-unlock-detailed-conditions.md) 一致。
- **设置**：语言（跟随系统 / 中文 / English / Español）、主题（跟随系统 / 浅色 / 深色）、登录自启状态、文件位置。

### 托盘

| 图标徽记 | 状态 |
|---|---|
| 绿色 ● | 运行中 |
| 黄色 ▲ | 离开确认中 / 需要设置 |
| 红色 ▲ | 已挂起（凭据错误） |
| 红色 ⊗ | 服务已停止 |
| ○ | 正在连接服务 |

- **单击**：速览面板（实时 dBm、60 秒曲线、状态）；
- **双击**：打开主窗口；
- **右键**：启动 / 停止 / 重启服务、查看日志、退出管理器（服务继续在后台运行）；
- **悬停**：两行提示，显示状态与设备信号。

## 九、判定规则概要

以下为默认值，都可以在「配置」页修改。完整、逐条的规则见 [`docs/lock-unlock-detailed-conditions.md`](docs/lock-unlock-detailed-conditions.md) 或管理器「判定条件」页。

### 状态

| 状态 | 含义 |
|---|---|
| 已解锁 | 正在使用电脑，监测是否离开 |
| 待锁定 | 锁屏提示已显示，等待确认离开或你回来 |
| 已锁定·等待离开 | 已锁屏，但还没确认你离开过（Win+L 后、刚锁屏时） |
| 已锁定·监控中 | 已确认离开，等待你回来自动解锁 |
| 解锁确认中 | 已推送凭据，等待登录结果（最多 20 秒） |
| 暂缓 | 点了「拒绝」或「N 分钟内不锁定」，暂时不判定 |
| 已挂起 | 凭据错误，停止自动解锁，直到改正 |

### 「批次全部达标」规则

- **触发**：先出现一个越过阈值的读数，它只用来启动批次，本身不计入；
- **收满**：之后连续 N 个读数**每一个**都越过阈值；
- **作废**：中间有一个不达标，整批作废，等下一次触发；
- **自动解锁**时相邻读数间隔不能超过 3 秒；**撤回提示**不限间隔（手表可能隔十几秒才广播一次）；
- 状态一变，进行中的批次清零。

### 默认流程

| 步骤 | 条件 |
|---|---|
| 已解锁 → 弹出提示 | 启动 / 唤醒后超过 15 秒；触发后再连续 **5 个**低于 -80 dBm |
| 提示 → 锁屏 | 提示出现后连续 **10 个**低于 -80 dBm |
| 提示 → 撤回 | 触发后再连续 **3 个**高于 -80 dBm |
| 锁屏 → 可解锁 | 触发后再连续 **5 个**低于 -80 dBm（确认真的离开过） |
| 可解锁 → 推送凭据 | 触发后再连续 **3 个**高于 -65 dBm |

### 设备停止广播（静默）

- 停播 3 秒以内不算任何证据（偶发丢包）；
- 超过 3 秒后，只有在**停播前已经连续 2 个读数低于锁定阈值**，或**连续「无信号判离开」时长（默认 180 秒，0 = 关闭）完全没有读数**时，才每秒补记一个 -127 的静默值计入离开批次；一个偶发的低读数不算；
- 信号还强时停播不算离开：手机和手表会为了省电间歇停播。

### 蓝牙接收卡死

扫描显示在运行，但连续 30 秒收不到周围**任何**设备的广播，判定为电脑蓝牙接收卡死（例如驱动超时）：

- 卡死期间不补记静默值，不会因为「没信号」而误弹提示或误锁屏；正在提示的会撤回；
- 自动恢复：先重启扫描 → 30 秒后仍无广播就重启蓝牙适配器（蓝牙耳机、鼠标会断开几秒再自动重连）→ 再过 60 秒仍不行就通知你手动关开蓝牙或重启电脑，之后每 5 分钟再试一次；
- 概览页「BLE 扫描」显示这个状态。

### 其他

- 从睡眠中恢复：清空读数，重新给 15 秒宽限；
- 手动解锁：回到「已解锁」；手动锁屏：进入「已锁定·等待离开」（已挂起时除外）。

## 十、配置参考

配置文件：`C:\ProgramData\BleUnlock\appsettings.json`。建议通过管理器「配置」页修改；手工编辑也可以，保存后服务会自动重新加载。

### 设备 `BleUnlock.Device`

| 键 | 默认值 | 说明 |
|---|---|---|
| `Irk` | 空 | 目标设备的 IRK（DPAPI 加密）。空或全零 = 未选择设备 |
| `IrkByteOrder` | `Auto` | IRK 字节序：`Auto` / `Normal` / `Reversed`。一般保持 `Auto` |
| `IdentityAddress` | `null` | 可选。设备用固定身份地址广播时按地址匹配，格式 `AA:BB:CC:DD:EE:FF` |

### 凭据 `BleUnlock.Credentials`

| 键 | 默认值 | 说明 |
|---|---|---|
| `UserName` | 空 | Windows 用户名：本地账户、`域\用户名` 或 UPN、微软账户邮箱 |
| `Password` | 空 | Windows 密码（DPAPI 加密）；空 = 只锁不解 |

### 判定 `BleUnlock.Proximity`

| 键 | 默认值 | 允许范围 | 说明 |
|---|---|---|---|
| `LockThresholdDbm` | -80 | 必须低于解锁阈值 | 读数**低于**它算离开；提示期间读数**高于**它算回来 |
| `UnlockThresholdDbm` | -65 | 必须高于锁定阈值 | 锁屏后读数**高于**它算靠近 |
| `LockPromptSampleCount` | 5 | 1–50 | 弹窗前需要的连续离开读数（也用于锁屏后确认离开） |
| `LockConfirmSampleCount` | 10 | 1–50 | 提示出现后锁屏前需要的连续离开读数 |
| `UnlockSampleCount` | 3 | 1–20 | 解锁（或撤回提示）前需要的连续靠近读数 |
| `SampleIntervalMs` | 0 | 0 或 100–2000 | 0 = 每条广播都计入；大于 0 时每隔这么多毫秒计入一个读数，期间没有新广播就重复上一个读数（重复的也算数，锁屏和自动解锁都会更快，也更容易受偶发读数影响）。蓝牙接收卡死时不重复；连续「无信号判离开」时长没有真实读数后也不再重复 |
| `StartupGraceSeconds` | 15 | ≥ 0 | 服务启动或唤醒后，这段时间内不判定离开 |
| `UnlockPendingTimeoutSeconds` | 20 | > 0 | 推送凭据后等待登录结果的最长时间 |
| `NoSignalDepartureSeconds` | 180 | 0 或 30–3600 | 完全收不到设备这么久就算离开（设备关机/被带走）；0 = 关闭。手表放着不动会停播一两分钟，太短会误锁 |

### 通知 `BleUnlock.Notification`

| 键 | 默认值 | 允许范围 | 说明 |
|---|---|---|---|
| `Mode` | `Toast` | `Toast` / `Dialog` | 提示方式。开了「勿扰」时 Toast 可能被静默吞掉，此时改用 `Dialog` |
| `RejectSnoozeSeconds` | 60 | > 0 | 点「拒绝」后多少秒内不再提示 |
| `SnoozeMinutes` | 5 | 0–240（不含 0） | 点「N 分钟内不锁定」后多少分钟内不再提示 |

### 界面 `BleUnlock.Ui`

| 键 | 默认值 | 说明 |
|---|---|---|
| `Language` | `system` | `system`（跟随 Windows）/ `zh` / `en` / `es`；其他系统语言回退为英语 |

### 示例

```json
{
  "BleUnlock": {
    "Device": { "Irk": "", "IrkByteOrder": "Auto", "IdentityAddress": null },
    "Credentials": { "UserName": "", "Password": "" },
    "Proximity": {
      "LockThresholdDbm": -80,
      "UnlockThresholdDbm": -65,
      "UnlockSampleCount": 3,
      "LockPromptSampleCount": 5,
      "LockConfirmSampleCount": 10,
      "SampleIntervalMs": 0,
      "StartupGraceSeconds": 15,
      "UnlockPendingTimeoutSeconds": 20,
      "NoSignalDepartureSeconds": 180
    },
    "Notification": { "Mode": "Toast", "RejectSnoozeSeconds": 60, "SnoozeMinutes": 5 },
    "Ui": { "Language": "system" }
  }
}
```

旧版键（`LockWindowSeconds`、`UnlockWindowSeconds`、`MinSamples`、`PromptTimeoutSeconds`）留在文件里也不再生效；管理器保存时既不写回也不删除它们。

### 生效方式

| 修改内容 | 生效方式 |
|---|---|
| 阈值、批次个数、超时、暂缓时长 | 下一次判定直接使用新值 |
| `Irk` / `IrkByteOrder` / `IdentityAddress` | 重建匹配缓存并清空读数历史 |
| 用户名 / 密码 | 重新预验证；通过则解除「已挂起」 |
| `Notification.Mode` | **需要重启服务** |
| `Ui.Language` | 立即生效 |

**校验与保护：**

- 配置无效（例如解锁阈值不高于锁定阈值、个数超出范围）：服务启动时拒绝启动（退出码 1，日志 `[FTL] 配置无效…`）；运行中热重载时拒绝这次加载、保留原配置。
- 设备或凭据**为空**不算无效：服务以「未配置」或「只锁不解」运行。
- 原本有设备或凭据，重新加载时却变成空值（多半是文件没写完或已损坏）：拒绝这次加载、保留原配置。要移除设备，请在管理器里「解除配对」。

### 调阈值的建议

- 打开「概览」页，坐在平时的位置看一会儿读数，再走到你希望锁屏的距离看读数；
- 锁定阈值设在「离开距离」的读数附近，解锁阈值设在「坐着」的读数稍低一点；
- 两个阈值之间留出足够的间隔（默认 15 dB），避免在临界位置反复锁 / 解；
- 也可以看日志里每 30 秒一行的「摘要」：状态、读数个数、平均 dBm、距上次匹配秒数。

## 十一、安全说明

- **加密保存**：`Device.Irk` 与 `Credentials.Password` 用 Windows DPAPI（机器范围）加密，密文形如 `dpapi:v1:…`。管理器保存时自动加密；手工写入的明文仍可用，但日志会提示「建议在管理器里保存一次以加密」。
- **密文绑定本机**：配置文件拷到别的电脑无法解密，需重新选择设备、填写密码。这能防止配置文件外发后泄露明文；本机管理员或 SYSTEM 权限的程序仍能解密（服务必须能还原密码，原理上无法避免）。
- **目录权限**：`C:\ProgramData\BleUnlock` 只允许 SYSTEM 和 Administrators 访问，普通用户读不到配置和日志。
- **IRK 不外露**：IRK 只通过仅限 SYSTEM / 管理员的本地管道传给管理器，不在界面显示，不写日志。
- **只在本机通信**：所有组件之间用本地命名管道，没有网络端口。
- **风险提示**：有人拿着你的手表 / 手机靠近你锁着的电脑，电脑会被解锁。请把它当作「便利功能」，而不是安全边界；高敏感场景建议只用「只锁不解」模式（不填密码）。

### 打单文件安装包

```powershell
.\installer\build-installer.ps1
```

产物：`installer\out\BleUnlock-Setup-<版本>.exe`。脚本会：

1. **确定版本号并打 git 标签**（[MinVer](https://github.com/adamralph/minver)）：
   - 有未提交的改动时拒绝打包，先提交，保证版本号一定对应某次提交（`src/BleUnlockService/appsettings.json` 除外，它可能带着本机的测试账号，且不进安装包）；
   - 当前提交已经有 `vX.Y.Z` 标签：沿用这个版本（同样的代码，同样的版本号）；
   - 否则在当前提交打一个新标签，补丁号加 1（`v1.0.0` → `v1.0.1` → …；第一次是 `v1.0.0`）。标签只打在本地，需要时用 `git push origin v1.0.1` 推送；
   - 编译时 MinVer 从标签读出版本号，写进服务、提示助手和管理器，管理器「设置 → 关于」显示「版本号（提交号）」，例如 `1.0.1（4880ccd）`；脚本最后会核对程序里的版本号与标签一致；
   - 平时直接编译（不经过打包脚本）得到的是 MinVer 的预发布版本号，例如 `1.0.2-alpha.0.3`，「关于」里会标注「本地开发版本」；
2. 自包含发布服务、助手和管理器（目标电脑不需要 .NET）；
3. 用 MSBuild 重新编译凭据提供程序（找不到 MSBuild 时使用最近一次的编译结果）；
4. 下载并校验 Visual C++ 运行库（缓存在 `installer\cache`，校验微软签名）；
5. **从 git 取配置模板**（默认 `HEAD`），所以本机工作区里填过测试账号的 `appsettings.json` 不会被打进安装包；`-TemplateRevision ''` 改为从暂存区取；
6. 用 Inno Setup 编译。

> 在 PowerShell 里给 `-TemplateRevision` 传空字符串时，请用 `& .\installer\build-installer.ps1 -TemplateRevision ''` 直接调用；经 `powershell -File` 转发会丢掉空参数。

## 十六、排障与常见问题

**服务起不来**
- 看 `C:\ProgramData\BleUnlock\logs\` 里的 `[FTL]` 行，以及事件查看器中来源为 `BleUnlock` 的事件；
- 最常见的是配置无效（如解锁阈值不高于锁定阈值），日志会列出具体是哪一项；
- 配置文件从别的电脑拷来时密文无法解密，需在管理器里重新选择设备、填写密码。

**设备列表是空的 / 我的设备显示「不支持」**
- 列表来自 Windows 蓝牙配对库，由服务读取；服务没运行时列表为空；
- 「不支持」表示配对时设备没有提供 IRK，按[第六节](#各类设备怎么配对)换一种配对方式；只能和自家 App 配对的手环无法使用。

**能自动锁屏，但回来不会自动解锁**
- 安装后还没锁过屏：凭据提供程序在锁屏界面出现时才加载，锁一次屏即可；
- 没有填写密码（「只锁不解」模式），或填的是 PIN；
- 锁屏后你没有离开过：Win+L 后要先离开再回来；
- 锁屏界面没有在显示：动一下鼠标或按任意键；
- 状态是「已挂起」：密码错误或已过期，在「配置」页改正；
- 连续 3 次推送没有结果后会暂停推送：手动登录一次即可恢复。
- 看日志里的「收到认证结果」一行：`NTSTATUS` 是总的结果，`子状态` 说明具体原因（如 `C000006A` 密码错误、`C0000064` 找不到用户、`C0000072` 账户已停用），挂起原因也会直接写出来。

**查看凭据提供程序的调试日志**（锁屏界面上发生了什么）
1. 管理员 PowerShell：`New-Item HKLM:\SOFTWARE\BleUnlock -Force; Set-ItemProperty HKLM:\SOFTWARE\BleUnlock CpDebugLog 1 -Type DWord`；
2. 以管理员运行 Sysinternals DebugView，勾选「Capture → Capture Global Win32」；
3. 锁屏后靠近设备，DebugView 里会出现 `[BLECP]` 开头的记录：使用场景、收到的用户名和密码长度、走哪种认证包、提交结果和子状态（不会记录密码内容）；
4. 用完后删除这个值：`Remove-ItemProperty HKLM:\SOFTWARE\BleUnlock CpDebugLog`。开关在登录界面进程启动时读取，修改后锁屏一次（必要时重启）才生效。

**没有弹出提示就直接锁屏了 / 根本没有提示**
- 「勿扰」或专注模式可能吞掉 Toast 通知，把「通知方式」改为「对话框」（`Mode = Dialog`，需重启服务）。

**坐在电脑前也被提示要锁屏**
- 看「概览」页的读数：如果平时坐着就接近 -80，把锁定阈值调低（如 -85），或把弹窗触发个数调大；
- 身体、金属桌面和设备所在的手腕 / 口袋都会明显影响信号。

**走回来要等很久才解锁**
- 把解锁阈值调低一点（如 -70），或把解锁确认个数调小；注意两个阈值之间仍要留出足够间隔。

**概览页「BLE 扫描」显示异常，或蓝牙耳机偶尔断开几秒**
- 这是电脑蓝牙接收卡死后的自动恢复（重启扫描或适配器）。频繁出现时，建议更新蓝牙驱动或关闭蓝牙的「允许计算机关闭此设备以节约电源」。

**管理器显示「无法连接到服务」**
- 服务没在运行：在概览页或托盘菜单里点「启动服务」；
- 服务刚启动或刚重启，管理器每 2 秒自动重试一次。
